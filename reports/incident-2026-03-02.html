1. Critical Issues & Fixes

CRITICAL FIXED Stuck Pending Rounds (Infinite Settlement Retry)

Affected Rounds: #59080193, #59079578 (both round_id % 3 == 2, Operator #2)

Symptom: "Settling round XXXX" log repeats every 15 seconds, but no TX is sent. Round shows as "Pending" in frontend forever.

Root Cause:

  • After round-manager restart, gap_cache is empty (in-memory only)
  • Two locations use if round_id in self.gap_cache: before setting settled=True
  • When a round's data came from get_cached_lock_gap (not local gap_cache), the entry doesn't exist
  • On-chain pre-check confirms settled=true and returns, but never marks cache → infinite retry

Fix: Changed both locations to self.gap_cache.setdefault(round_id, {})

# Before (broken):
if round_id in self.gap_cache:
    self.gap_cache[round_id]["settled"] = True

# After (fixed):
self.gap_cache.setdefault(round_id, {})["settled"] = True

File: services/round-manager/app/scheduler.py (lines ~333, ~457)

Sentry Reference: TimeExhausted for round 59079578 (120s TX timeout)

HIGH FIXED Telegram Notifier MarkdownV2 Parse Error

Symptom: Railway warns every 15 seconds: Telegram send failed: 400 ... can't parse entities: Character '.' is reserved and must be escaped

Root Cause: telegram_notifier.py uses MarkdownV2 parse mode but doesn't escape special characters (., $, ,) in formatted numbers like $1,234.56

Fix: Imported escape_md() from bot_formatters.py and applied to all dynamic values. Also escaped . in static URLs (gfex.io → gfex\\.io).

File: services/round-manager/app/telegram_notifier.py

HIGH INVESTIGATING Telegram Mini App Auth — Invalid Hash (403)

Symptom: Users opening GFEX via Telegram see "!" error: API 403: {"error":"Invalid hash"}

Root Cause (suspected): TELEGRAM_BOT_TOKEN on Vercel doesn't match the bot token Telegram uses to sign initData
